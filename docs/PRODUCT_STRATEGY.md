# AIGATE 产品战略

裁决日期：2026-09-07（Asia/Hong_Kong）。状态：产品方向已确认，本轮交付文档；具体功能和商家合同按后续里程碑实施。
当前事实见 [CURRENT_STATUS](CURRENT_STATUS.md)，阶段验收见 [ROADMAP](ROADMAP.md)。本文件是当前产品战略唯一主入口。

## 1. 根本目的与经营逻辑

让准备使用或购买 AI 服务的人，更快理解模型、价格、使用方式、服务商和风险，做出有证据的选择，并前往合适的官方站、第三方或明确披露关系的我方站点。长期建设可持续、自扩展、在 AI 购买决策领域具备领先可见度的导流业务。

SEO 和 GEO（生成式搜索与答案引擎可见性）是获客手段。用户价值来自比较和选择，商业价值来自能解释、能交付、能续约的曝光和导流。顶尖排名是经营愿景，尚无排名、收入或流量数据证明已达成。

经营闭环：真实需求 -> 可信数据与内容 -> 有用比较和工具 -> 搜索/答案引用/社群/回访 -> 有效站外导流 -> 赞助收入与商家反馈 -> 数据、内容和体验再投入。每次扩张同时预算更新、审核、纠错和维护成本。

## 3. 用户价值与可竞争的产品

主用户是想使用 AI、但在订阅、API、中转、价格和准备条件之间难以选择的个人；开发者与小团队使用相同数据获得更细的单位成本与覆盖信息。商家购买曝光与效果服务，不能购买事实。

一次有效体验应让用户看懂：适合什么任务、成本如何计算、数据何时更新、哪些限制未确认、为什么推荐或排除某个选项、接下来去哪里。用户也可以得出“暂不购买”或“选官方”的结论，这属于有效帮助，但不计入导流北极星；用满意度与放弃原因作为护栏，避免诱导点击。

免费基础：搜索、同单位比较、来源时间、自然榜、帮助和实用工具。迭代顺序是先补足可信比较，再让选购代理缩短路径，让商家后台证明导流价值。

## 4. 自然评分、赞助排名与关联关系

### 已选的双榜规则

页面可先展示明确标注的“赞助推荐/广告”，其后是独立自然榜与完整目录。商业排序只作用于赞助库存。改变赞助状态、购买期限或我方关系后，自然候选、分数与相对顺序必须保持不变；将其作为未来回归测试。

透明综合评分是确认的方向，尚无新评分算法获批。候选维度包括来源可验证性、新鲜度、可用率、延迟、模型覆盖、可比成本和用户反馈；只使用证据可支持的维度。不同来源的统计口径先校准，缺失值标缺失，不能伪造为零或优秀。方法版本、权重、样本窗口、缺失处理、并列规则和申诉渠道必须公开后才发布总分。

现有 Hvoy rank 是上游中转参考；现有 site.score 的初始 50 不等于可信综合评分。既有赞助置顶也不证明双榜隔离已完成。M1 要逐条核对现有逻辑，再决定迁移。

### 我方中转站和商业站

明确纳入商业路线。先完成固定赞助曝光试点，再接入用户指定的我方站点。位置附近披露“自营”或“关联商业站”；若占用赞助位，同时保留赞助属性。所有自然排名适用同一规则，不因自营自动排首，不隐藏对其不利的有效事实。

未来接入前登记：站名和精确域名、经营/关联主体、公开产品范围、目标页、允许字段和 Feed、更新时间、站点负责人、关系披露、归因口径和退出路径。未指定域名时不推定任何现有商家为我方。

自营点击、第三方赞助收入、自营站确认转化与实际毛利分别核算。内部推广价值不能同时计作外部赞助营收与自营交易收入。交易发生在目标站，AIGATE 当前承担比较与导流职责。

## 5. 商业模式、交付与单位经济

| 顺序 | 产品与付款方 | 实際交付与成立证据 |
|---|---|---|
| 首先 | 固定赞助、付费排名、品牌广告；商家付款 | 约定版位、周期、展示材料、关系标注、曝光与点击报告、缺量/中断处理；不承诺自然名次或成交 |
| 然后 | 我方站点导流 | 指定目的地、关系披露、独立归因；有目标站授权反馈后才报告转化 |
| 随后 | 商家月度增值套餐 | 资料/Feed 健康、投放报告、需求趋势；商家愿意续费才扩大功能 |
| 条件成熟 | CPC/CPL/CPA 等效果收费 | 合同明确定义有效行动、排重、无效流量、撤销/退款和对账；当前先卖固定交付 |
| 后续 | 数据/API/报告 | 独立外部客户反复需要且愿付费，且数据权利、质量和成本足够 |

报价依据是可交付库存、目标用户价值和支持成本，不照抄大平台费率。先验证少量可交付版位，避免搭建竞价拍卖系统或同时引入多种计费。

经营核算：可归属收入减直接内容、数据、服务、销售支持与退款成本，得到业务贡献毛利；我方站点的下游毛利单独报告。观察商家续费、投放交付、收入集中度、用户决策完成率和投诉，收入增长但用户价值下降时减少商业密度。

## 6. 持续自扩展：数据与内容两条回路

数据回路：已批准来源/授权 Feed -> 既有 raw -> 校验与独立 merge/import -> 标准模型、计划、SKU、商家及价格关系 -> 比较页 -> 需求/纠错 -> 数据修补。

内容回路：搜索无结果、用户问题、来源变化、可用的 Search Console 汇总 -> 机会队列 -> 更新现有页、增加工具、新增页面或拒绝 -> 来源复核与索引决策 -> 观察用户动作 -> 更新/合并/退役。

保留历史设计中的“机会队列”：每项记录用户任务、需求证据、差异价值、数据充分度、维护成本、负责人、影响页面和拒绝理由。先保证更新与纠错能力，再增加页面族；缺少增量价值的关键词组合优先用现有页面筛选解决。

每个页面族有发布/索引/过期/回滚规则。index 表示可公开索引；noindex 用于证据不足但需要访问的页面；merge/retire 处理重复或失去价值的页面。noindex 不能替代来源许可、数据审核或隐私处理。

采集架构遵循 [生命周期](collection-data-lifecycle.md)。需求发现可以提出新来源候选，不能自动扩大精确来源白名单。采集、自动发布与生产运行位置按既有规则管理。

## 7. SEO/GEO 和分发

按“模型选择 -> 使用路径 -> 价格比较 -> 商家判断 -> 准备条件”建立主题入口；有真实差异数据才建立模型/商家/套餐页。计算器、比较器和可分享结果带来直接使用价值与引用。中英文质量分别验收，避免机械翻译大量重复页。

提供可读取正文、来源日期、稳定实体名称、清楚的方法和限制、规范链接、正确 canonical 与结构化数据。GEO 观察使用固定问题集，记录引擎、时间、回答和实际引用 URL；不把一次提及当稳定排名，也不把 llms.txt 当引用保证。SEO 以合规分析数据和人工采样观察，不能靠未获许可的搜索抓取制造指标。

Google 的政策要求规模化内容提供实际价值，并对广告/赞助链接作恰当标记；此处采用有用比较与清楚披露的方向。[Google 搜索政策](https://developers.google.com/search/docs/essentials/spam-policies)（2026-09-07 查阅）

社群承接反馈、需求与回访，合作分发后置于内容质量。每轮只设一个主要增长假设，记录改了什么、看什么指标、何时继续或停止。

## 8. 两项优先创新及验证顺序

### AI 选购代理（已选 B）

输入任务、预算、原生界面/API、模型和支付等必要偏好；从已验证目录输出对比方案、预计费用口径、适合/不适合原因、证据时间和外部下一步。先做一个需求场景，先证明比现有列表更易决策；缺少证据就展示未知或回到比较页。商业卡与自然建议独立。

可先验证规则选择器，再评估是否需要 LLM 解释层。可信数据和可重复的推荐规则先于聊天表现；不收集账号、密钥或付款凭据。

### 商家增长系统（已选 C）

先提供资料完整度、Feed 新鲜度、版位交付和有效导流报告；随后按聚合需求提示缺少的模型覆盖和内容机会；最后再评估线索、实验和付费数据产品。商家不能读取可识别用户的搜索历史，线索转交需要用户同意。

冷启动可用固定赞助试点的人工报告验证价值；有人持续使用并愿意续费后才建设复杂后台。最小可信档案是支撑能力，完整 Trust Passport、开放评价社区、履约争议系统不是二者的前置大项目。

第二曲线保留但后置：价格变化提醒、历史成本、只读摘要、嵌入组件和 API。每项先验证需求、权利和复用收益，再投资。
