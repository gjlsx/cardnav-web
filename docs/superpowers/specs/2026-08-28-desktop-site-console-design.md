# AI LoveMoney 本地网站总控台设计

## 目标与边界

把现有 `scripts/collection/gui.py` 扩展为本机 Python/Tkinter 桌面总控台，使日常采集、正式网站数据编辑、合作审核与受控运维不依赖网页后台。它可在本机开发，未来可在远程机器运行；生产网站不运行采集器。

本期根 Tab 固定为：`采集数据`、`网站配置`、`合作运维`。`采集数据`的子 Tab 固定为：中转网站、卡网商品、官方网站、模型排行。每个页面均为“左侧操作/记录选择 + 中央配置或详情 + 底部独立运行日志”的单窗口布局；不再以多个独立窗口或单页表单替代。

不做网页管理后台、Electron、SSH 配置编辑器、自动下单、登录/验证码采集、生产服务器爬虫或没有来源批准的真实 HTTP 请求。

## 已确认的核心规则

1. 来源配置只有 `enabled`、`interval_minutes`、`max_items_per_run`、类别和优先级；默认 `false`、`60`、`1000`，`0` 表示不限。手工运行忽略 `enabled`，仍服从单次上限。
2. `site.score` 是网站展示排序，当前样例统一 `50`；来源使用类别/priority，绝不使用来源分数覆盖站点分数。展示稳定排序为 `score DESC, name ASC`。
3. 来源优先级为本站 API > 本站公开网页 > 聚合站；聚合站内部为 PriceAI > CardNav > OpenPrice；同优先级同站同商品以最低有效价决胜。
4. 请求先保存来源级 raw 响应。清洗以稳定键匹配：卡网商品为 `站点规范域名 + canonical SKU`；其他实体按对应规范键。命中手工锁定或手工隐藏的记录，保留 raw 审计但不生成 staging、也不更新正式数据。
5. 正常且可映射的 staging 自动发布到正式网站表/快照；未知映射、冲突和校验异常进入待处理。手工保存则事务写入正式数据并立即刷新网站读取数据。
6. “删除”是手工隐藏，不物理删除；取消手工状态后必须重新采集并走完整 raw → staging → 正式发布流程，不能恢复旧快照。
7. raw 记录保存解析后的明细；允许保存公开、白名单的完整响应以审计，完整响应保留 30 天后可清理，解析字段与运行审计长期保留。Cookie、账号、验证码、订单、交付信息和凭据不得入库或日志。
8. 采集器在本机运行，GUI 可启动/停止本地调度器；各来源独立配置。首次运行不自动启用任何来源。生产发布只通过运维 Tab 的明确动作执行；备份、恢复、发布均需二次确认并写入该 Tab 日志。

## 数据流

`collection_sources → collection_runs / raw payloads / raw records → collection_staging_observations → publisher → 既有正式表与 public_snapshot_entries`

`collection_staging_observations` 是唯一权威 staging 表：p012 以兼容、增量迁移方式扩展它，不新建或并行维护 `collection_staging_records`。手工覆盖/隐藏放在独立的覆盖表，不把采集原始数据改写为人工数据。发布器在每条记录处理时检查覆盖表；同一次总快照仍可为未锁定记录获取和处理，锁定记录仅跳过清洗和发布。

## 分期

第一阶段先建立可迁移数据库合同、Python 服务层与全部 Tab；随后连接现有 fixture/approved-source 工作流。已批准且字段白名单明确的来源可真实 HTTP 采集并写入**本机** MySQL `ailovemoney`，而不是只输出 fixture；定时器默认关闭。MVP 不直接连接远程 MySQL，服务器发布经合作运维 Tab 的明确发布动作按 `howtorunvpsnew.md` 执行。远程 MySQL 可从本机直连读写是 MVP 后的独立任务。生产部署遗留任务 `t08281547.p008` 不成为本总控台的依赖。

## 验收

- 可从一个 `python gui.py` 入口打开三根 Tab、四个采集子 Tab、各自日志和异步任务状态。
- 每类正式数据可定位单条记录，编辑、隐藏、解除手工锁定均可审计；锁定记录不被正常采集发布覆盖。
- 批量来源响应即使包含锁定记录仍完整落 raw；其余记录可继续进入 staging/正式表。
- 独立来源调度配置能保存并在禁用状态下不自动运行；人工运行可用。
- MySQL/CLI 单元测试、桌面实际入口冒烟和网站正式数据读取验证通过；密钥不进入 Git 或日志。
