# AIGATE 可持续自扩展增长战略设计（三方案待统一裁决）

日期：2026-08-31  
状态：战略候选，不代表用户已批准实施  
事实基线：[`../../CURRENT_STATUS.md`](../../CURRENT_STATUS.md)

## 1. 对任务的理解与重述

用户的根本意图不是再做一个静态网址目录，而是把 AIGATE 建设成一个能长期经营的 AI 决策入口：持续发现真实需求，合法获取并校验公开数据，把数据组织成对用户有新增价值的比较、指南和工具，在搜索与 AI 答案场景中赢得可持续可见度，把高意向用户导向合适的官方站、服务商、工具或合作入口，并形成透明、可归因、可复投的收入。

“自扩展”在本设计中的严格定义是：

```text
真实需求信号
  -> 机会评分与人工/规则审批
  -> 补齐许可来源和标准实体
  -> 生成有独特决策价值的候选页面/工具
  -> 质量闸门决定 index / noindex / 拒绝发布
  -> 用户行为、纠错、新鲜度和转化反馈
  -> 刷新、合并、下线或发现下一项需求
```

它不是“输入关键词 -> AI 批量改写网页 -> 自动索引”。Google 明确把主要为操纵排名而规模化生成、抓取拼接且缺少增量价值的页面列为 scaled content abuse；因此页面规模只能是价值和证据的结果，不能成为北极星本身。

## 2. 建议的项目根本目的

> 让任何准备使用或购买 AI 服务的人，在十分钟内从“我不知道该选什么”走到“我理解选择、证据、价格、风险和下一步”，并让每次真实选择反过来提升整个决策系统的准确性、覆盖度和商业效率。

这句话包含四个不可交换的部分：

1. **用户任务**：完成选择，而不是浏览更多页面。
2. **可信证据**：来源、采样时间、比较单位和商业关系可见。
3. **复利系统**：每次查询、点击、纠错、更新都能生成结构化反馈。
4. **商业分离**：收入可以影响曝光库存，不能改写自然排序事实。

## 3. 三套完整母战略

### 方案 A：信任型 AI 决策引擎（阶段推荐）

- 核心用户：第一次或低频购买 AI 订阅/API/相关服务的个人和小团队。
- 核心产品：需求问答、可比价格、来源与新鲜度、风险提示、决策清单、工具。
- 增长方式：高意向问题集群 + 可复用免费工具 + 可引用的原始分析。
- 收入方式：清晰披露的 CPA/CPL/按点击合作、固定赞助库存、后续会员提醒。
- 优点：最贴合现有内容、数据和页面；先建立信任再变现；范围可控。
- 风险：需要持续编辑判断；联盟供给可能不稳定；早期收入上限有限。
- 成立条件：能证明用户完成决策并产生可归因外跳，而非只有页面访问。

### 方案 B：AI 服务垂直市场与商家操作系统

- 核心用户：买方和希望获取合格线索的网关、卡网、服务商。
- 核心产品：验证商家档案、报价/库存同步、询价、线索、商家后台、服务水平记录。
- 增长方式：供需双边网络、商家自传播、品类页与地域/模型覆盖页。
- 收入方式：商家订阅、验证费、CPL、明确标注的推广位、交易服务费。
- 优点：收入更直接，商家有更新数据的动力，可形成网络效应。
- 风险：审核、纠纷、欺诈、售后和监管成本显著增加；容易伤害自然排名公信力。
- 成立条件：已有稳定高意向流量、归因系统、商家审核和申诉能力。

### 方案 C：AI 访问数据与 API 基础设施

- 核心用户：开发团队、采购团队、研究者、媒体和其他目录/Agent。
- 核心产品：标准模型/计划/供应商图谱、价格与可用性历史、变更流、API、嵌入组件、研究报告。
- 增长方式：被引用的数据、开发者集成、开放摘要数据、合作分发和 AI 答案引用。
- 收入方式：API 分层订阅、数据授权、告警、企业报告和白标组件。
- 优点：边际成本低、复购强、最可能形成长期数据护城河。
- 风险：数据权利、准确度、SLA、历史数据质量和销售周期要求最高；当前基础尚不充分。
- 成立条件：数据覆盖、新鲜度、稳定键、变更历史和外部需求都被持续验证。

### 阶段推荐，不是最终裁决

推荐 **A 打地基 -> B 验证商业闭环 -> C 提升护城河**。三者不是同一天并行开工：A 先证明信任和意图，B 在不出售自然排名的前提下把意图产品化，C 只在数据质量与外部付费需求成熟后启动。若直接从 B 开始，容易成为付费黄页；若直接从 C 开始，容易在没有客户和稳定数据时过度建设。

## 4. 九项关键决策：每项三方案

### 4.1 根本定位

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| AI 网站/商品目录：回答“有哪些”。实现快，但容易同质化。 | AI 决策引擎：回答“我该选哪个、为什么、下一步是什么”。**阶段推荐**。 | AI 访问基础设施：向人和机器提供可信数据与接口。长期候选。 |

裁决触发器：若用户主要使用搜索/列表，A 足够；若比较、过滤、详情和工具能提升决策完成，选 B；若外部团队反复索取结构化数据或告警，升级 C。

### 4.2 首个必赢用户群

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 新手个人：不懂模型、订阅、网络、支付与渠道。现有向导最匹配，**阶段推荐**。 | 开发者/小团队：关心模型覆盖、API 单位价、稳定性和切换成本。 | 商家/渠道：关心曝光、线索、报价同步和信誉证明。 |

裁决触发器：按站内搜索、落地页来源、外跳目标和用户访谈确认，不凭“市场大”选择。首期只能有一个主画像，其他画像是次级入口。

### 4.3 核心承诺

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| “最快找到入口”：以覆盖和导航速度取胜。 | “十分钟做出更安全、更省钱的选择”：以完成决策取胜，**阶段推荐**。 | “持续监控价格、可用性与变化”：以持续情报取胜。 |

裁决触发器：承诺必须能用行为事件验证。无法测量的“最全、最好、最权威”不进入公开文案。

### 4.4 护城河

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 编辑品牌：深度指南、实测、作者可信度。 | 决策图谱：模型、计划、地区、价格单位、渠道、风险、工具之间的可解释关系，**阶段推荐**。 | 双边网络：买方意图与商家更新/履约信号形成网络效应。 |

裁决触发器：编辑内容能带来品牌搜索则加强 A；跨页面结构化关系能提高完成率则加强 B；只有在真实买卖双方都持续参与时才声称 C。

### 4.5 自扩展机制

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 编辑驱动：人工选题、写作、复核、发布。质量高但扩张慢。 | 证据驱动队列：需求信号自动建候选，系统补数据/草稿，人审和质量门槛决定索引，**阶段推荐**。 | 自治发布：系统自动生成、发布、刷新和下线，人只抽检。速度最高、搜索与信任风险也最高。 |

裁决触发器：B 只有在每个页面族都有固定数据合同、价值差异、测试和下线规则后才启用。C 至少要在 B 连续多个周期低错误、低人工返工后重新立项；当前不建议。

建议的“需求雷达”输入有三类，互不冒充：

- 第一方：站内搜索零结果、过滤无结果、详情到外跳、工具使用、纠错和收藏/提醒意愿。
- 外部：Search Console 查询/页面、公开趋势和获批来源变化；只存必要聚合信息。
- 商家：结构化更新与声明；默认不可信、不索引，验证后才进入事实候选。

建议的页面发布闸门同时要求：明确意图、至少一个独有比较/计算/工具价值、足够来源、可比单位、可见采样时间、无敏感字段、可用正文、内部链接、canonical、索引策略和过期策略。数字阈值由后续实施任务配置化，不在战略文档写死为运行规则。

### 4.6 增长渠道

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 搜索主题集群：围绕高意向任务建立少量深页面和决策页。 | 免费工具产品化：计算器、比较器、检查器、提醒器带来自然分享和回访。 | 社群/合作分发：Telegram、QQ、商家组件、媒体数据引用和联合内容。 |

阶段推荐：A 负责可发现，B 负责可用与回访，C 负责分发；每个周期只押一个主增长实验，避免无法归因。

搜索策略不是“关键词铺页”，而是“一个真实任务对应一个最佳入口”。同一意图的地区、模型、价格方向等组合应优先在交互页内解决；只有组合本身有足够独特数据与独立需求时才生成独立 URL。

### 4.7 商业模式

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 绩效导流：CPC/CPL/CPA，靠可归因高意向行动收费。最贴合决策引擎，**首个验证项**。 | 商家 SaaS/赞助：验证档案、数据同步、询价箱、固定推广库存按月收费。 | 数据/API：变更流、历史、告警、嵌入组件和研究授权按量/订阅收费。 |

成熟模式启示而非照搬：NerdWallet 的公开年报把独立编辑内容、比较工具、数据市场与按 click/lead/action/funded-loan 收费连接起来；Yelp 的公开年报展示了广告为主、同时扩展订阅、API 数据许可和交易分成的组合。AIGATE 可以学习“多层收入结构”，但必须先证明自己的用户意图和供给质量。

商业底线：

- 赞助位和自然结果分区展示；付费不能提升自然分数、来源优先级或“最佳”结论。
- 每个佣金/线索关系在推荐或外跳附近清晰披露，不能只在页脚写一句泛化声明。
- 先卖可交付价值，再定价格；早期用有限合作试点验证，不先造复杂计费系统。
- 暂不自营账号、代持资金、担保交易或处理售后争议；这些会把项目推入完全不同的风险与运营模型。

### 4.8 信任、排序与治理

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 来源披露：显示来源、采样时间和“非实时/上游参考”。 | 方法透明：再公开归一化、入选/剔除、纠错、商业披露和更新方法，**阶段推荐**。 | 可审计信誉层：商家验证、履约/纠错历史、申诉和用户证据；运营成本最高。 |

三个数据层必须分开：

1. **来源事实**：第三方公开数据、原字段和采样时间。
2. **AIGATE 判断**：可解释规则、编辑结论和置信度。
3. **商业关系**：赞助、佣金、免费样品、合作或数据提供关系。

用户评价若未来开放，应默认 `noindex`、链接 `ugc/nofollow`、先审核后进入聚合值。不能把商家提交直接变成可索引详情，也不能购买、压低或选择性隐藏评价来改变公众印象。

### 4.9 北极星与经营仪表盘

| 方案 A | 方案 B | 方案 C |
|---|---|---|
| 有效自然流量：合格非品牌点击与目标查询覆盖。容易测，但可能奖励无效访问。 | 已验证决策完成数：用户完成比较/工具/关键指南后执行可归因下一步，**阶段推荐**。 | 贡献毛利与复访：按意图/页面族计算收入减直接数据、内容和合作成本。最商业，但需先有归因。 |

建议的指标树：

```text
北极星：每月已验证决策完成数
├── 获客：合格非品牌点击、直接/品牌访问、合作引荐
├── 价值：比较完成率、工具完成率、决策路径退出点
├── 信任：来源覆盖、新鲜度、纠错率、错误恢复时间、披露覆盖
├── 商业：可归因外跳、合格线索、每决策收入、合作续费
└── 效率：每个有效索引页成本、刷新成本、人工复核分钟、毛利
```

绝对“顶尖排名”应拆成三种可验证候选：A 为一组高意向查询进入前十，B 为核心决策查询进入前三并贡献稳定非品牌点击，C 为搜索与 AI 答案都持续引用 AIGATE 的独有数据。基线建立前不填写目标数字。

## 5. 深度发散：可形成第二增长曲线的产品种子

以下每项仍给三种形态，避免把一个灵感误写成唯一答案。

### 5.1 AI 选择器

- A：五问静态向导，直接复用现有指南。
- B：基于预算、任务、是否需要原生 UI/API、支付和风险承受的可解释推荐器。
- C：用户保存偏好，价格/可用性变化时重新计算并提醒。

### 5.2 总拥有成本计算器

- A：官方订阅地区价换算。
- B：统一模型调用单位、估算月度使用量并比较官方/API/中转。
- C：团队账单导入、本地分析和切换建议；不得上传密钥或完整账单到公共站。

### 5.3 价格与可用性变更流

- A：页面显示“自上次采样变化”。
- B：按模型/计划订阅邮件或 Web Push 提醒。
- C：付费 API/Webhook，向团队或其他 Agent 提供变更事件。

### 5.4 可信商家档案

- A：来源与更新时间完整度徽章。
- B：域名/公开联系/报价同步/纠错响应的分层验证。
- C：履约与争议历史；只有拥有审核、申诉、证据和法律流程后才考虑。

### 5.5 AIGATE Index

- A：不计算总分，只展示分项事实。
- B：发布透明方法的分项指数，例如价格透明度、数据新鲜度、模型覆盖；不合成为“最好”。
- C：综合评分与榜单；解释和博弈成本最高，现阶段不建议。

### 5.6 面向 AI Agent 的决策接口

- A：继续维护 `llms.txt` 与清晰可引用页面。
- B：提供公开只读 JSON 摘要、来源与时间戳。
- C：提供有配额、SLA、历史和 webhook 的商业 API。

## 6. 内容与页面系统设计

### 6.1 页面不是内容单位，决策任务才是

建议先建立需求图谱，再决定页面形态：

```text
用户意图
  ├── 选择模型
  ├── 选择使用方式
  ├── 比较价格/地区/单位
  ├── 选择渠道或商家
  ├── 准备网络/支付/KYC
  ├── 解决具体操作
  └── 监控变化
       ↓
模型 — 计划 — 地区 — 使用方式 — 渠道 — 商家 — 风险 — 工具 — 证据
```

每个公开入口必须回答一个任务，并提供至少一个“其他页面没有的可操作增量”：计算、标准化比较、变更历史、第一方实测、来源差异、决策树或工具结果。

### 6.2 三态发布模型

- **index**：证据充分、独有价值明确、可用且新鲜。
- **noindex**：候选页、商家自报、低覆盖组合、过期但暂时需要用户访问的页面。
- **retire/merge**：无需求、重复、长期过期或没有增量价值；重定向到更完整任务页。

### 6.3 质量预算

每增加一个页面族，必须同时预算：数据来源、人工复核、刷新频率、纠错入口、下线规则、分析事件和维护所有权。无法承担完整生命周期时，不建立该页面族。

## 7. 决策与授权边界

本设计可直接指导文档和测量任务，但以下事项必须在后续 tasklist 中得到用户明确裁决：

- 选择 A/B/C 母战略或批准推荐的阶段组合；
- 新增任何真实采集来源、采集频率或远程运行位置；
- 自然排序/指数方法、商家验证等级或用户评价系统；
- 联盟链接、付费曝光、线索收费、订阅或 API 定价；
- 自动发布、自动索引、提醒发送和任何真实外部消息；
- 处理账号、付款、担保、交易、售后或争议。

## 8. 外部依据

- [Google：Creating helpful, reliable, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) — 强调原创信息、实质增量、明确主目的和满足用户任务。
- [Google：Spam policies for Google Web Search](https://developers.google.com/search/docs/essentials/spam-policies) — 规模化低价值生成、抓取拼接和滥用站点声誉属于风险边界；高质量联盟页应提供原创评测、比较或额外信息。
- [Google：AI features optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) — 面向 AI 搜索仍要求非商品化、独特、可靠内容，不能为搜索变体批量造页。
- [Google：Product structured data](https://developers.google.com/search/docs/appearance/structured-data/product) — 非直接交易的比较/评测页可考虑 product snippet，但结构化数据必须与页面真实内容一致。
- [FTC：Endorsement Guides Q&A](https://www.ftc.gov/business-guidance/resources/ftcs-endorsement-guides-what-people-are-asking) — 佣金关系应在推荐/链接附近清楚、醒目披露。
- [NerdWallet 2025 Form 10-K](https://www.sec.gov/Archives/edgar/data/1625278/000162527826000014/nrds-20251231.htm) — 一手披露其编辑内容、比较工具、数据市场与 click/lead/action 等合作收入结构。

## 9. 本设计的自审结果

- 无“最全/第一/自动成功”承诺；排名目标被拆成需先建基线的候选结果。
- 每个关键战略项均有 A/B/C 三方案，推荐与批准状态分离。
- 商业模式不改变自然排序，联盟/赞助必须就近披露。
- 自扩展有 index/noindex/retire 闸门，遵循现有 raw-first 和生产只读边界。
- 本设计没有授权代码、采集、商业合同、自动发布或生产变更。
