# AI LoveMoney 数据导航与本地采集 MVP：范围、决策与交接

## 1. 用户目标

本任务在 `D:\work\dock\cardnav-web` 完善数据导航站 `https://ai.lovemoney.live`。当前样例与信息层级首先参考 CardNav（中转站/模型覆盖、官方计划详情）和 PriceAI（标准商品、最低价、有缺货渠道计数）；OpenPrice 仍在未来聚合源登记中，但不作为本轮首批样例的必要来源。不得复制第三方页面、图片或完整文案。数据运行时使用 MySQL `ailovemoney`，PostgreSQL 继续弃用。

本轮既要把当前空白的中转网站和官方网站补成有来源、可见且明确非实时的参考样例，也要做出下一阶段采集的可运行本机工具基础。用户已经明确要求：先默认本机开发测试，但工具可迁移到远程机器运行；生产公开站只展示，不能成为爬虫运行节点。

## 2. 已确认产品决策（不可省略）

### 展示

- 路由不变：`/llm-gateway`、`/official-price`、`/guide` 保持。
- 显示名：中文“中转网站 / 官方网站 / 帮助”；英文“Gateway sites / Official sites / Help”；俄文“Сайты-шлюзы / Официальные сайты / Помощь”。桌面、移动、首页入口、SEO 和用户可见帮助入口同步；仓库 README 与设计文档也更新。
- `/shops` 默认是一行一个标准 SKU 的商品聚合，而不是商家 SKU 堆叠。至少显示平台、商品、类型、最低参考价、币种、渠道总数、有货/缺货渠道、采样时间与样例标记。点入或切换后才显示商家/渠道；无购买外链。
- 目录必须统一“模型”和“订阅计划”：模型（如 GPT）与订阅计划（如 ChatGPT Plus、ChatGPT Pro 5x）都是可点击的标准目标；订阅计划通过显式关系映射到模型族。目标详情页显示两组内部结果：提供该计划的卡网商品（最低价与渠道数）以及支持映射模型族的中转网站（按站点评分降序）。没有关系时显示“尚无已验证关联”，不猜测。
- 官方订阅详情以 `https://cardnav.xyz/official-price/chatgpt-pro-5x` 的可理解信息层级为参考：可切换计划、地区报价表、内部“查看相关卡网 / 查看支持模型的中转站”入口；本站保留自身品牌和非实时样例说明。
- 首页热门卡网与 `/shops` 用同一聚合结果；中转网站与官方网站首页模块不能再是空白。
- `catalog_products` 是标准 SKU 权威表，包含 slug、平台、产品类型、显示名、别名。未知别名进入人工待确认队列，采集过程不能自动创建权威产品。
- 同优先级内按规范化目标网站名称去重；若同一标准 SKU 仍重叠，保留最低参考价。所有站点初始 `score=50`；MVP 后再以分数排序展示。
- 多源覆盖：本站公开 API > 本站公开网页 > 聚合站；聚合站内 PriceAI > CardNav > OpenPrice。高优先级有效字段不能被低优先级覆盖，低优先级只能补空字段。
- 所有展示数据明确为“公开参考样例 / 非实时”，保留短来源 URL 和时间。不得承诺实时、推荐购买、官方保证；未核实商家官网/邀请 URL 留空。
- 模型排行榜必须不是空页面。数据模型至少区分 `programming`、`creative_writing`、`math`、`image_generation`、`video_generation`；“视频生成”标签和分类记录本轮必须存在，但在没有可核验样例时其内容可为空，并显示诚实空态。其他分类使用少量公开参考样例形成可见排行榜；不声称通用真实性或实时评测。
- 采集数据与展示 DTO 分层：数据库 staging 可保存白名单内的详细站点身份、平台族、模型/计划覆盖、价格单位/币种/周期、库存/状态、地区、支付/交付标签、公开性能或稳定性字段、观测时间、字段级来源与置信度；公开页面仅选择用户决策所需的紧凑字段，绝不保存完整 HTML、Cookie、账户或私密订单信息。

### 采集工具

- 使用 Python，形态是本机 CLI + 独立人工 GUI，交互方式参考 `D:\work\dock\PriceAI-Monitor`，但不复用其自动下单/告警逻辑。
- 可在本机或将来远程机器运行，开发测试默认本机。数据库写 MySQL 的 staging 层；公开快照发布必须单独人工/规则批准，默认不自动发布。
- 每个来源独立配置且必须具备：`enabled`、`interval_minutes`、`max_items_per_run`。默认分别为 `false`、`60`、`1000`；`0` 代表不限制。人工点击可忽略 `enabled=false`，但仍遵守每次条数上限。
- 来源类别：独立卡网站、三个聚合站、API 提供者；采用平台族适配器（NewAPI/OneAPI、独角/LikeShop 类等）而非一域名一套 CSS。首批字段和样例先按 CardNav、PriceAI 两个参考站的可见结构设计；OpenPrice 仍是 `draft` 补充源。
- 真实网络采集有额外授权门槛：来源登记需包含批准状态、robots/条款结论、字段白名单、频率、保留期；未批准来源的 GUI/CLI 只能配置校验和本地 fixture dry-run，必须跳过网络。没有批准时不猜测、不批量请求。
- 永不登录、绕验证码/反爬/付费墙、访问购物车；不保存 HTML、Cookie、账户或交付说明。每域低并发、可识别 User-Agent、ETag/内容 hash 变更检测。
- 不在本任务安装 Windows 计划任务、线上 cron 或启动常驻定时。配置和 manual-run 能力可完成，后续用户逐来源批准后再启用。

## 3. 数据与代码约束

- 种子只影响明确标记的 `reference-*` / `is_sample` 数据；必须幂等；不得覆盖 `popular-search-terms`。
- 修复上一轮已知问题：`reference_data_sources.is_sample` 默认 false；商家官网 URL 与来源页面分开、未知官方 URL 为空；`(source_id, standard_product, site_id)` 自然唯一键；packed 协议升级或显式兼容并有测试。
- 示例：中转网站 4–8 站及少量可见模型价/模型覆盖；官方价格覆盖 ChatGPT、Claude、Gemini、Grok，每项 2–3 地区；模型排行榜包含至少一个非空文本/能力分类和视频生成分类记录。只使用公开可见短字段；不编造延迟、存活率、评分来源或官方实时保证。
- MySQL 连接信息只从本机已有 `.env` 读取；不能提交密码、SSH 密码、导出 SQL、cookies、token 或完整第三方响应。
- 不改 LikeShop 代码、数据库或端口 `8086`、`8090`、`8095`。

## 4. 发布与验证

- 本地先验证 MySQL 计数、种子幂等性、Python 工具 dry-run/staging、`pnpm test`、`pnpm run typecheck`、`pnpm run build`。
- 浏览器必须从首页真实导航进入 `/shops`、`/llm-gateway`、`/official-price`、`/model-leaderboard`、`/guide`，在 zh/en/ru 检查新入口；同时检查移动布局。必须点击至少一个模型或官方计划，确认内部关联结果包含卡网与评分排序的中转站。直打 URL 仅为补充证据。
- 发布只更新独立站 `ai.lovemoney.live`，Apache 80/443 反代独立 Node 服务。通过既有 LikeShop VPS 指南的运行方式和安全登录信息执行，但不把任何登录信息写入仓库/日志。
- 发布后检查 DNS/host-header 或真实域名 HTTPS、HTTP 80，以及 `dtch.yg2022.top:8086/shop/`、`8090/mobile/`、`8095/admin/` 均仍返回可用响应。生产服务器不运行 Python 采集器、不启动调度。

## 5. 人工参与处理约定

用户要求全程自动执行。只有下列操作因缺少明确逐来源授权而不得自动完成：对真实目标发起网络抓取、安装任意定时任务、将采集 staging 自动发布为公开快照。遇到这些情况，任务实现默认采用安全选项：来源登记为 `draft`、网络步骤跳过并记录原因、定时禁用、公开发布禁用。其余开发、数据样例、测试、文档和独立站发布均自动执行。
