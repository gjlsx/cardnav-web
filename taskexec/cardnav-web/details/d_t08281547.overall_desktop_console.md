# 总体任务：AI LoveMoney 本地网站总控台

## 目的

把当前仅能编辑来源和 fixture dry-run 的 `scripts/collection/gui.py` 升级成一个本机 Python/Tkinter GUI，可管理网站采集、正式数据和合作/运维；用户不必依赖网页管理后台。运行地点可为本机或日后远程服务器，当前开发与验证使用本机 MySQL `ailovemoney`。不把采集器部署到 `ai.lovemoney.live`。

## 已确认布局

- 总 Tab：采集数据、网站配置、合作运维。
- 采集数据子 Tab：中转网站、卡网商品、官方网站、模型排行。
- 每页：左侧操作与列表；中间配置、列表或精确编辑区；底部该页独立保留的输出日志。后台任务不得冻结 Tkinter UI。
- GUI 视觉/交互可参考 `D:\\work\\aiwork\\autoai\\matrix.py` 的 Notebook + 每页日志，也可借鉴 `D:\\work\\dock\\PriceAI-Monitor` 的后台线程、队列、按钮状态；不能复制其自动下单或把其 JSON 快照架构当作本站数据库架构。

## 数据和采集规则

1. 所有采集先进入来源 raw 表，再由本地清洗整合为 staging，最后写入既有正式 MySQL 表与公开快照。
2. raw 保存来源运行、响应元数据、白名单公开响应（完整体保留 30 日）、解析明细和 hash；严禁密码、Cookie、账号、验证码、订单、交付/售后敏感内容。
3. 正常 staging 自动发布。未知 SKU/计划/模型、同键冲突、无法解析的币种/单位和质量异常留在待处理，不自动展示。
4. 手工编辑或隐藏在正式数据旁保存覆盖标志与审计版本。卡网稳定键为规范化站点域名 + canonical SKU；其他分类有相应稳定键。手工标志存在时该记录只能展示手工数据，清洗跳过它；批量 HTTP 响应仍可保存 raw 并继续处理其余记录。
5. “删除”实现为 `hidden`，不物理删除；取消手工状态后必须重新采集，不能从旧 raw 或快照直接复原。
6. 来源配置：`enabled=false`、`interval_minutes=60`、`max_items_per_run=1000`、`0=不限`；人工运行绕过 enabled 但不绕过上限。每来源独立配置。来源无 `score`；站点展示分 `site.score` 当前统一 50。
7. 优先级：本站 API > 本站公开网页 > 聚合站；聚合站 PriceAI > CardNav > OpenPrice；同优先级同对象取最低有效价格，高优先级可覆盖有效字段、低优先级只补空。
8. 不登录、不验证码、不购买、不抓图片、不绕过 robots/条款。真实 HTTP 只允许 GUI 中已批准、白名单明确的公开来源；初始所有来源和调度关闭。

## 运行与安全

- 备份、恢复、发布需要双重确认，分别写入合作运维 Tab 日志。
- 不建立 SSH 配置编辑器；生产发布仍遵循项目根目录 `howtorunvpsnew.md`，并保持 LikeShop `8086/8090/8095` 不受影响。
- MySQL/SSH/邮件密码和导出 SQL 不得提交或写进 tasklog。

## 完成标准

从 `python scripts/collection/gui.py` 打开总控台，所有 Tab 可用，数据编辑能立即影响本地网站运行数据，自动入库遵守手工覆盖，来源调度默认不触发。完成后通过 Python 测试、TypeScript 测试/构建、实际 GUI 冒烟和本地网站读取验证；生产发布不在本任务范围内。
