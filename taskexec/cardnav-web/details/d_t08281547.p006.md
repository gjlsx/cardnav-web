# p006 Python 详细采集 CLI 与人工界面 MVP

## 实施

在项目内创建便携 Python 工具（建议 `scripts/collection/`），借鉴 `D:\work\dock\PriceAI-Monitor` 的配置编辑、手动测试、运行日志和本机 GUI 体验，但不引入其自动下单、通知或计划任务。采集层需要比展示层详细，但只能保存审批字段白名单；公共页面 DTO 必须继续紧凑。提供：

- CLI：配置检查、fixture/dry-run、写入 MySQL staging 的本地演练、可打印可审计的合并统计；MySQL 连接仅从环境读取。
- GUI：可编辑/保存来源配置、手动运行安全 dry-run、查看输出；手动运行忽略 `enabled=false`，但不忽略 `max_items_per_run`。
- staging observation 最少覆盖：规范化站点身份/域名、来源/来源等级、平台族、模型/订阅计划覆盖、价格+币种+计费单位/周期、库存/状态、地区、支付/交付标签、可公开的性能字段、字段级 `observed_at`/provenance/置信度。禁止保存完整 HTML、Cookie、账号、订单/交付详情或未列入白名单的正文。
- 配置的每来源字段至少 `enabled`、`interval_minutes`、`max_items_per_run`、`score`、来源类别、目标域名、优先级、批准状态、字段白名单。默认 `false`、`60`、`1000`、`50`；`0` 表示不限。
- 数据规则：按规范化目标站名去重；同优先级重叠时选最低价；本站 API > 本站网页 > 聚合站，聚合站按 PriceAI > CardNav > OpenPrice。高优先级覆盖有效字段，低优先级仅补空。
- 三个聚合站、独立卡网站、API 提供者均有独立配置条目；初始均为 `draft`/禁用，未获得逐来源批准时绝不发 HTTP 请求。首批 source/fixture 结构优先对齐 CardNav 与 PriceAI；OpenPrice 保留 draft 补充源。无批准时只使用本地 fixture 演练 staging。

不安装 Windows 计划任务、服务、cron；不做真实批量抓取、不自动 publish staging。运行地点可以是本机或未来远程机器，但本轮仅本机开发测试。

## 验收

- Python 单元测试覆盖配置默认值/`0`、不批准来源的跳过、上限、优先级合并和同级最低价。
- GUI 至少能启动并完成本地配置校验或 fixture dry-run，不暴露凭据；CLI 对本地 MySQL staging 有可重复的匿名计数验证。
- 文档写明未来真实来源、调度和公开发布需要用户逐项批准。
