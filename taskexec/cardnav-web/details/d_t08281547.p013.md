## Work

将现有 fixture/approved adapter 的统一流程实现为：创建 run → 保存来源 raw payload 与解析 raw record → 白名单/标准化/优先级去重 → 查 `ManualOverride` → 未覆盖行写唯一 staging 表 `collection_staging_observations` → 质量通过者自动发布到现有 `shop_sites/shop_products/gateway_sites/gateway_model_coverage/gateway_model_prices/official_prices/model_leaderboards` 与其实际读取的 `public_snapshot_entries`。正式写入与快照更新必须一个事务；失败不显示半快照。

为已批准、公开且 allowlist 明确的 source 接通真实 HTTP adapter：人工运行时（即使 `enabled=false`）真实采集并写入**本机** MySQL `ailovemoney` 的 raw/staging/正式表；`enabled` 只控制调度，draft source 仍只用 fixture。真实网络适配器必须复用同一 pipeline，不允许另建绕开 raw、手工标志或质量门的写入路径。

实现批量响应规则：即使某条稳定键被手工锁定，来源级 raw 和其它行仍处理；被锁定或 hidden 的行不产生 staging、不覆盖正式数据。取消覆盖本身不发布旧数据，下一次新 run 才会改变它。保留 API > 网页 > 聚合及 PriceAI > CardNav > OpenPrice；同级/同站/同键最低有效价决胜；无有效数字价格不得错误排在有效最低价前。

## Acceptance

- 单测覆盖批量 raw、锁定跳过、hidden 跳过、解除后需新 run、优先级、同级最低价、异常停 staging、事务失败回滚。
- 未批准来源继续 fixture-only、`network_requests=0`；已批准 adapter 的测试以本地 HTTP fixture server 验证真实请求和本机 MySQL 入库，不把公开外站网络可用性作为测试前提；不安装调度器。
- 网站 public 表/快照的更新使用现有 DTO/格式，不改公开路由。
