# p023 来源级抓取控制与受控测试按钮

## 用户可见行为

每个“采集数据”子 Tab 的左侧针对当前选中来源提供：`抓取一次`、`开始循环抓取`、`停止选中来源`、`测试选中来源`。来源不是硬编码按钮；新建来源后同样可被选择和控制。右侧为选中来源配置，增加 `test_script`：仅允许项目 `scripts/collection/source_tests/<source-id>/test.py` 的受控相对路径。测试按钮以当前 Python 执行该脚本，日志显示命令、stdout/stderr、退出状态；无脚本时明确报错，不执行任意命令。

## 停止语义

每个来源有一个 `threading.Event` 运行标志。停止时设置标志、禁用该来源后续循环，并写 `task <source-id> is stop!`。抓取流水线在 fetch 后、每条清洗/入库前及发布前检查标志；停止后结束 run 为 `stopped`，不发布已暂存的部分结果。不能取消已进入 urllib 的单次 HTTP 读取，但其 15 秒超时后必立即遵守停止标志。

## 循环

开始循环后立即执行一次，之后由 Tk `after` 按该来源 `interval_minutes` 调度；运行中不重叠。停止该来源只影响该来源；关闭 GUI 停止全部循环。`enabled` 保留为“允许批量/全页调度”的配置，不替代来源级开始按钮。

## 验收

- 单元测试覆盖停止前/处理中/发布前的 pipeline 行为、来源循环避免重叠、停止输出、受控 test.py 拒绝越界路径和 stdout/stderr 返回。
- GUI smoke 检查四个子 Tab 都有新来源级按钮。
- 全量 collection 测试和前端测试通过；不向 draft 来源发真实 HTTP。
