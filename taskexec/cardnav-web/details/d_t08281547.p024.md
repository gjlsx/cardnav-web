## Confirmed baseline to preserve

This task reconciles the final product decision recorded before the desktop-console implementation:

```text
one local collection batch (one or more selected sources)
  -> retain source raw payloads / raw records
  -> normalise, validate, deduplicate and merge all eligible batch candidates
  -> show the merged result for review
  -> user explicitly clicks "入库实际运行数据表"
  -> one transaction updates entity tables and public snapshots
```

- The local collector writes only the local MySQL `ailovemoney` database. The production web host never collects.
- A source response may always be retained as raw audit data. If its stable record key is manually locked or hidden, it must not create/update a staging candidate, a merged candidate, or formal display data.
- Natural keys remain: shop `normalised_host + canonical_sku`; gateway `normalised_host`; official plan `plan_slug + country_code`; leaderboard `task_slug + normalised_model`.
- Source conflict order is own API > own public HTML > aggregator; aggregators are PriceAI > CardNav > OpenPrice. A lower-priority source may fill a missing field but may not replace a valid higher-priority field. Equal priority valid prices choose the lower price. `site.score=50` is display order only, never source conflict priority.
- A regular or scheduled collection must never write formal tables or public snapshots. It only creates a pending batch. User-triggered source tests remain fixture-only and never publish.
- The current single staging table remains `collection_staging_observations`; this task must not introduce `collection_staging_records` or a second staging table.
