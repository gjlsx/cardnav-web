# p026 Explicit merge-and-import runtime publisher and bounded legacy-data recovery

## Fix sources

`FIX:t08281547.p013,t08281547.p016,t08281547.p019`

## Work

Create the only permitted runtime-data transition: `merge_import_batch(batch_id)`. It reads the unified raw rows from one completed local batch, applies validation/manual flags, deduplicates and merges all matching stable keys, then updates the existing entity tables and complete `public_snapshot_entries` snapshot in one transaction. Writing those runtime tables is publication; do not create a second publish/copy step. Capture, dry-run, source test, and source loop must not invoke it directly.

The API/CLI must require an explicit manual `merge-import` action and return a count/status suitable for the desktop button. A future scheduler may call the same action only when its separate `merge_import_enabled=false` default is deliberately enabled; it may never use a different code path. The operation must be idempotent for a batch, reject incomplete/unknown batches, record an activity/audit event without secrets, and preserve current public data if the transaction fails.

Before changing records, implement a diagnose-first recovery command/report for formal rows created by the legacy direct-publish collector. The automated repair may touch only records that are provably legacy collector/fixture data by recorded run/source provenance; it must back up those bounded rows locally and rebuild their snapshots from the last explicitly published batch. Any ambiguous row must be listed for human review and left untouched. Never clear the whole `ailovemoney` database and never alter user sample/manual rows.

## Acceptance

- Tests prove runtime tables/snapshots remain byte-for-byte/row-count unchanged after capture, loop, dry-run, and test.
- Tests prove only `merge_import_batch` updates runtime data and that retrying it is safe; its source-priority merge covers priority winner, null-field fill, and equal-priority lower-price winner.
- Tests cover a lock/hide added after raw collection but before merge/import; raw remains while runtime update is skipped.
- Local MySQL recovery test proves only known legacy collector rows are backed up/rebuilt; ambiguous/user rows remain intact.
