# t08292201.p037：独立 merge/import worker 运行约束与采集引擎定案

## 用户确认的运行边界

- 来源采集只保存批准来源的统一 raw payload / `collection_raw_records`；不得直接写运行时表。
- raw 的读取、合并、清洗与运行库/快照事务写入由本机独立 worker 承担；该 worker 默认关闭，必须人工或显式启用。
- worker 是单例、单线程、串行执行：持续轮询间隔为 10 秒；每次只处理一个 `raw_completed` batch，完成或失败后才检查下一个 batch。它不采集网页、不处理登录/验证码、不改生产服务器。
- worker 调用既有 `merge_import_batch`，保留其稳定键、手工闸门、同级最低价、来源优先级和 24 小时新鲜度规则；所有候选超过 24 小时时不隐藏既有运行时记录，页面继续显示最后采样时间。

## 采集引擎决策

记录 `D:\work\dock\testcatch` 的重跑结果和方法缺陷，作为项目选择依据：三种 HTTP 客户端均能读取 PriceAI 公开页；下游 LDXP 返回人机验证/挑战页，不能作为可采来源。基准不得用浏览器伪装、验证码滑块、TLS 指纹规避或 `ROBOTSTXT_OBEY=False` 作为能力评分。

本期只记录架构：后续获批准的真实来源采集适配器首选 Crawlee for Python 的 `HttpCrawler`；仅在已批准页面确实必须渲染 JavaScript 且不涉及验证码/访问控制时使用其 `PlaywrightCrawler`。实际接入时要设置单 worker 的并发上限为 1，并把响应先写 raw。`curl_cffi` 不作为规避访问控制的手段，Scrapy 不作为本项目首选新接入引擎。

## 验收

1. 生命周期和数据导航文档均明确 worker 边界、10 秒轮询、单例串行与默认关闭。
2. 文档记录重新执行的 HTTP 对照事实和基准失真原因，避免把伪造分数或验证码脚本作为决策证据。
3. 不改生产部署、MySQL 数据、真实来源批准状态或已有采集代码。
