# PriceAI Crawlee 浏览器采集与本机入库：总体要求

## 已确认目标

建立一个新的独立 Python 采集程序。它使用 **Crawlee for Python + PlaywrightCrawler** 访问已批准的公开网页；即使页面静态，也不走 HTTP-first 或旧 `urllib`/`requests` 路径。首批精确允许的入口只有：

| Source ID | URL | 页面类型 | 既有数据类 |
|---|---|---|---|
| `priceai-card-subscriptions` | `https://priceai.cc/channels` | 卡网订阅 | `RecordKind.SHOP_PRODUCT` |
| `priceai-official-api` | `https://priceai.cc/official-api` | 官方 API / Token Plan | `RecordKind.OFFICIAL_PLAN` |
| `priceai-transit-api` | `https://priceai.cc/api-transit` | 中转 API | `RecordKind.GATEWAY_SITE` |

这三项均为 PriceAI 聚合公开参考页，不是向页面中的商户或上游服务发起采集。程序不得跟随链接，不得处理登录、验证码、CAPTCHA、挑战、人机验证或任何访问控制绕过；请求失败应保留安全的状态摘要并结束该来源。

## 结构与数据流

1. 一个来源控制文件集中管理 1 至未来多站的 source id、精确入口 URL、启用状态、页面类型与采集范围。
2. 一个独立页面解析模块按站点和页面类型，把浏览器页面内容变换为项目现有的数据类、稳定键和字段白名单。
3. 一个独立 MySQL 持久化模块负责 raw 写入、查询及调用既有 merge/import 基础设施；不得新建平行业务 schema。
4. 浏览器采集只落 `collection_raw_payloads` / `collection_raw_records`。独立 merge/import worker 以 singleton 单线程、默认关闭、每 10 秒串行轮询执行，清洗、去重及调用既有运行库/快照写入。

高优先级来源在其有效 raw 的 `captured_at` 距当前不超过 24 小时时，低优先级不得覆盖其已有有效字段，只能补空；高优先级超过 24 小时未采到有效 raw 时，低优先级可接替。保留历史运行数据和前端显示的上次扫描时间，不隐藏旧记录。

## MySQL 连接与 CLI

新持久化门面使用仓库根 `.env` 的 `MYSQL_*`，目标本机 `127.0.0.1:3306/ailovemoney`。在同一活动 CLI/worker 的安全窗口内复用连接，默认 `connection_idle_ttl_s=600`；每个 batch 使用独立短事务，空闲到期、异常或进程退出时关闭。不得逐条记录反复打开/关闭连接，也不得把连接或事务无限期占用。

CLI 至少提供：配置校验、来源列表、采集一个或全部允许来源、查看 raw 批次、单次 merge/import、启动或观察 worker。浏览器并发上限固定为 `1`。旧 `scripts/collection/` 保留不删，需明确 legacy，且新 CLI/worker 不得调用其旧采集入口。

## 验收和排除

- 先运行解析、持久化、worker 和 CLI 的自动化测试，再执行真实网页采集。
- 真实采集仅在本机手动启动，实际 raw 不写 Git、日志、task detail 或 QA 报告。
- 验证 raw 批次、运行库记录和公开快照；随后通过受管本地 Astro `http://127.0.0.1:3101/` 三类入口验证读取。先以 `pnpm exec astro dev status` 确认入口。
- 不在生产站部署或调度该程序；不改变用户已有 `README.en.md`、`README.ru.md` 未提交修改。
