## 任务 1 头脑风暴：后备采集源

公开页观察（2026-08-30，只看用户给出的入口，未打开商家官网）：

| 候选 | 公开形态 | 可采字段（入口页可见） | 与现有源关系 |
|---|---|---|---|
| aiapipk 首页 | 「中转站竞技场」列表 | 站名、相对价格倍率（openai/claude/gemini/deepseek 等）、模型族标签、「访问官网」外链 | 另一家聚合，不是 5 星评分；更像性价比倍率 |
| GitHub `hvoyai/awesome-ai-api` | README 实时排行表；另有 `data.json` / `index.html` | 排名、站名、在线率、平均延迟、模型数、厂商、用户评分、支付/退款/发票；README 写明数据来自禾维 AI | 与 `hvoyai.com/sites` 同源镜像 |
| `hvoyai.com/sites` | 「AI 中转站综合排行榜」 | 站名、模型覆盖数、认证、平均在线率、平均延迟、支付、退款、发票、用户评价（如 4.6(8)）；本页约 40/86 站；站内详情 `/sites/{slug}` | 综合榜主源；GitHub 表是它的备份 |

建议锁定（执行 p001 时写成正式来源合同，未经 p001 不得真实 HTTP）：

1. **主源 / 镜像不要双写同一排行。** `hvoyai.com/sites` 作为综合榜、在线率、延迟、用户评价的主源。GitHub 只登记一个精确 URL（优先仓库内 `data.json` 或 README，p001 二选一），优先级低于禾维站点，只在主源 24 小时内无有效 raw 时补空。不要把 GitHub 和禾维排行当成两个独立排名系统。
2. **aiapipk 是第三家聚合，不是同一套评分。** 其可见值是模型族相对价格倍率，不是 0–100 的本站 `site.score`。映射前必须在 p001 写清：是写入 `gateway_model_prices`、只作 raw 审计，还是按明确公式换算展示分。禁止把 `openai 0.6` 直接写成 `site.score=0.6`。
3. **精确 allowlist，禁止配置加 URL。** 建议源 id（p001 可改名，不可改成任意 URL）：
   - `aiapipk-gateway-arena` = `https://www.aiapipk.com/`
   - `hvoyai-sites-ranking` = `https://www.hvoyai.com/sites`
   - `hvoyai-awesome-ai-api` = 选定的 GitHub 精确 URL
   - 模型套餐/价格对比：`/sites` 列表**没有**逐模型 token 价。p001 必须在 **hvoyai 同域**找到精确价格页再登记；找不到就记 gap，不得为了价格去跟「访问官网」或商家域名。
4. **同域详情可选项。** 仅当列表缺字段时，才允许类似既有 `cardnav-gateway-details` 的同域 `/sites/{slug}` 规则。仍禁止下游商家站。
5. **稳定键继续用 `host + 规范化站名/host`，`RecordKind.GATEWAY_SITE`（价格用既有价格表）。** 不新建业务 schema。与 PriceAI / CardNav 已有站按 host 去重；高优先级有效字段 24 小时内不被低优先级覆盖。建议优先级：本站已有 CardNav/PriceAI 覆盖与手工分 > 禾维综合榜（uptime/latency/user rating）> GitHub 镜像 > aiapipk 倍率。
6. **`site.score` 政策。** 公开列表当前按评分降序，展示说明仍是「即将上线」。后备源的用户评价（约 1–5 分）不得悄悄冒充本站自有公式。p001 必须二选一并写测试：  
   - A. 只把禾维用户评价换算到 0–100 填空（例如 `round(rating*20)`），已有非默认手工分不覆盖；或  
   - B. 采集分另存展示字段，不改 `site.score`。  
   默认建议 A，且 `50` 的采集初值可被有效评价替换，手工锁/隐藏记录仍跳过。
7. **合规。** 每源先查 robots/公开条款；失败则该源 `blocked`/`partial`，不得绕过。真实采集仅本机、默认 `enabled=false`。raw 正文不进 Git / tasklog / QA。
