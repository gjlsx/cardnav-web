# AIGATE 项目战略、目标与路线图任务总说明

## 用户意图

在完整阅读中英文 README、当前状态、既有采集与发布文档、活动 tasklist 和实际代码入口后，完成三份相互分工的项目文档：

1. 更新 `docs/CURRENT_STATUS.md`，如实总结当前进度，区分当前代码事实、历史验证证据、文档陈旧项和未实现能力。
2. 新建 `docs/superpowers/specs/2026-08-31-aigate-sustainable-growth-design.md`，定义项目根本目的，并对每个关键战略决策提供 A/B/C 三套方案、取舍、触发条件和推荐顺序。
3. 新建 `docs/GOALS_MILESTONES_ROADMAP.md`，建立可衡量的目标、里程碑、路线图、停止条件和每个里程碑的保守/平衡/进取三条路径。

项目意图是建设一个可持续、自扩展、在 AI 选型/价格/渠道决策细分领域争取顶尖自然搜索排名并产生可衡量导流价值的网站。这里的“自扩展”必须是数据和需求驱动、经质量闸门发布，而不是批量生成低价值页面。

## 必须保留的项目事实

- 生产公开站只读；采集只在本机、精确 allowlist、raw-first，显式 merge/import 后才写运行时表和快照。
- 不得新增第二套 schema、staging 流水线、浏览器写生产数据或生产服务器采集器。
- 不跟随下游商家链接，不绕过 robots、登录、验证码、CAPTCHA、挑战页或访问控制。
- AIGATE/aigate.live 是当前公开品牌与主域；旧域跳转和 LikeShop 独立服务边界必须保持。
- 商家提交、赞助、合作入口已存在，但提交结果不自动公开。
- README 和 `docs/CURRENT_STATUS.md` 存在新旧事实错位，文档应明确标示，不得顺手改运行逻辑。
- 现有工作区有用户未提交改动；本任务只修改本说明列出的文档和 taskexec 元数据。

## 商业与搜索约束

- 参考成熟的“编辑内容 + 比较工具 + 数据市场/导流”、目录广告/订阅/API、交易或行动分成模式，但不得把第三方模式当作本站已验证收入。
- 联盟、赞助、付费排序和商业关系必须清晰披露；自然排序与商业曝光必须分离。
- SEO 目标服从用户价值和原始增量价值；禁止为排名批量生成薄页、搬运拼接、伪评测、虚假评分或无证据的“最佳”结论。
- 所有动态索引页应有最小数据充足度、来源、新鲜度、唯一价值和 noindex/下线规则。
- 不承诺绝对“第一名”；使用可验证的领先指标、落后指标和分阶段目标。

## 三方案输出规则

事实总结不伪造选择题，但从产品、数据/工程、商业/增长三个视角汇总。战略设计中的每一个决策项必须给 A/B/C 三个互斥或清晰可组合的方案。路线图中的每一个里程碑必须给保守、平衡、进取三条路径，并说明推荐默认、切换触发器和停止条件。

## 验收

- 三份交付物职责清晰、互相链接、没有互相矛盾的当前状态。
- 战略设计至少覆盖根本目的、目标用户、价值主张、护城河、自扩展机制、增长渠道、商业模式、信任与合规、核心指标九项，每项三方案。
- 路线图至少覆盖基线、质量、需求图谱、决策页、导流归因、商家闭环、数据/API 飞轮和规模化治理。
- 每个里程碑有可量化退出条件；硬编码业务阈值均标记为“候选门槛，需在实施任务中配置化并验证”，不得冒充已批准运行参数。
- 引用外部资料时使用可访问的官方或一手来源链接；不复制长段落。
- 通过 Markdown 结构检查、相对链接存在性检查、禁用占位符检查和 `git diff --check`。

## 明确不做

- 不修改应用代码、数据库、采集配置、生产服务器、README 业务文案或现有用户改动。
- 不执行真实采集、发布或浏览器流程。
- 不把方案推荐当作用户已批准的产品实现。
- 不输出内部逐字思维链；只记录可核验的依据、取舍和结论。
