## Steps / Verification

- [ ] 首先记录源码中的缺失风险：默认零分、首屏与动态行差异、没有模型能力榜的现行采集项。
- [ ] 用只读本机 MySQL 会话检查 model_leaderboards 和 model-leaderboards 快照的分组、样例标记和缺失字段；不得调用 initializeMySqlSchema/seed/merge，也不直接打印载荷/凭据。可用汇总 SQL：

```sql
SELECT source_id, task_slug, source_board_slug, is_sample, COUNT(*) AS rows_count,
       SUM(score IS NULL) AS missing_score_count,
       MIN(sampled_at) AS earliest_sampled_at, MAX(sampled_at) AS latest_sampled_at
FROM model_leaderboards
GROUP BY source_id, task_slug, source_board_slug, is_sample;
```

- [ ] 核对 runtime 与快照是否一致；如库不可访问，报告“运行数据未核验”，不能将源码样例当实际库存。该任务实际数据审计未完成时用 partial/blocked，不写 done。
- [ ] 对现有记录的公开出处做有限人工查证（仅 HTTP(S) 公共榜单/方法/许可页面，不跟随商户交易、群链接，不新增自动采集）；不得把用户指定渠道理解为公开群抓取授权。
- [ ] 对照 PriceAI/CardNav/OpenPrice 历史信息层级，列“已具备/本单修复/后续”三列，不重做全站竞品报告；日期不同的旧截图只作历史证据。
- [ ] 审计自检：任一 source 的零分是否真有值？样例能否被误认为当前？转载方是否被称为测评执行方？服务商参考是否被当模型能力？任何一项无证据就明确 unknown。
- [ ] 完成 QA、任务日志与根规则提交链。

## Done / Gates

done 仅表示审计完成，不表示来源获采集许可或所有数据可发布。来源不合格不是让执行者“想办法抓到”的任务，p003 按下述诚实降级显示。新源的精确 URL、字段、许可与刷新频率需单独建单确认。
