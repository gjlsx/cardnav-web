# p004 最小自有事件端点与存储

Depends：无业务任务依赖；执行仍须本单先获批准。必读 Overall 参数表。不是广告计费平台。

## Files / Interfaces

Create：src/measurement.ts、src/measurement-config.ts、src/pages/api/measurement.ts、scripts/measurement-report.ts（本任务先提供配置核验/建表命令）、test/measurement.test.ts、test/measurement-api.test.ts。
Modify：src/store.ts（复用既有懒初始化 MySQL pool，增加窄范围事务方法，不整文件重构）、src/database.ts（新增两个统计表的建表语句）、.env.example。
使用既有 MySQL ailovemoney，不建新数据库或采集 schema。迁移仅创建统计表，不重建商品/榜单表；测试 DDL 幂等后方可在获批本机验证。

可复现 CLI：`pnpm exec tsx scripts/measurement-report.ts --check-config` 只输出非敏感配置及目标是否本机；`pnpm exec tsx scripts/measurement-report.ts --init-schema` 只执行本任务两张统计表的幂等 DDL。src/database.ts 导出窄范围 initializeMeasurementSchema，不能借此运行全库初始化/种子。配置核验不连接或写库；建表必须先核对 MYSQL_HOST/PORT/DATABASE 解析为本机目标，拒绝远程地址。DDL 测试不得在用户业务表上试验回滚。

导出接口：
- readMeasurementConfig(env): { enabled, environment, retentionDays, maxEventBytes, maxEventsPerDay }，键/默认见 Overall。
- validateMeasurementEvent(input: unknown): MeasurementEvent | null。
- recordMeasurementEvent(event: MeasurementEvent, receivedAt: Date): Promise<'accepted' | 'duplicate' | 'limited'>。
- 查询/清理函数供 p006 CLI 使用；参数化 SQL，不接收任意 SQL、表名或外部 URL。

MeasurementEvent 固定字段：
eventId（随机 UUID）、sessionId（随机 UUID）、name、pageKind、entityId、sourceId、channel、placement、targetKind。除必需身份/事件/页面字段外，其余可空；长度/枚举校验。
name = ranking_view / evidence_open / comparison_enter / comparison_interact / outbound_click。
pageKind = leaderboard / gateway-list / gateway-model / gateway-detail。
channel = google / qq / telegram / xiaohongshu / x / bilibili / substack / youtube / direct-or-unknown。
placement = natural / sponsored / unknown；targetKind = official / third-party / owned / unknown。
实体 ID 只用已展示的目录稳定 ID，不传完整 URL/搜索词。unknown 保留，不由商家名称推断归属；来源标识不证明客户端可信。

存储：measurement_events（event_id 唯一键、session_id、received_at、上述受限维度；时间和会话索引）；measurement_daily_limits（日键、accepted_count、limited_count）。不存 IP、UA、Cookie、headers、原请求正文或出站 URL。日计数在同一事务锁定，事件唯一冲突不再扣名额；失败回滚。限额是资源上限，不是反作弊证明。

两表增加 environment，由服务端 MEASUREMENT_ENVIRONMENT 赋值；日配额键为 environment+day，查询按 environment 过滤。浏览器不得提交/覆盖环境；本单仅启用 local-test 验证，生产字段留给以后部署。测试事件即便随历史数据保留，也不能被报表当真实经营事件。
