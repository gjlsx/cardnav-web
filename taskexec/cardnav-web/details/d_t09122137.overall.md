# AIGATE M1 中转站自然榜与赞助展示可信隔离：总体任务说明

## 1. 执行状态与目标

本文件对应 `taskexec/cardnav-web/tasklist09122137.md`。当前是**待用户审查的执行单**：所有行均为 `todo`，由 `grok` 在 wind 明确确认后执行。Codex 仅负责建单与自审，未开始代码、采集、部署或数据变更。

M1 的目标不是发明新的评分系统，而是把已经存在的中转站结果页面变成可长期信任的导流入口：用户始终可以看到一份不受商业关系影响的完整自然榜；合作商家可以购买独立、醒目、可识别的赞助展示。

## 2. 已确认的不可突破边界

1. 付费排名可以获得靠前或独立展示，但必须清楚标为“赞助”/“合作商家”。
2. 赞助、联盟、自有中转站或商业关系不得改写自然候选集合、自然排序、自然评分或自然榜结论。
3. Hvoy、其他公开榜单、上游可见分数和已有 `site.score = 50` 都只是公开参考或既有展示字段；上游算法、样本及权重未公开时，不得改称 AIGATE 自有综合评分。
4. 赞助外部目标同时需要可见文字/视觉标识与 `rel="sponsored noopener noreferrer"`；来源参考链接不得因其本身被误标为付费。
5. 更正入口应当低摩擦、可追溯，但本 M1 不新建工单后端、CRM 或自动化处理系统。

## 3. 本清单的最小产品合同

### 3.1 两条互不污染的展示路径

- **自然榜**：由当前公开、可说明的事实字段按既有自然规则排序，列表完整展示。赞助状态不是该排序键，赞助置顶不能插入或遮蔽自然结果。
- **赞助展示**：仅从明确的赞助/合作状态中取得，视觉和文案与自然榜区分。某合作商家若按自然事实也应进入自然榜，可在自然榜中照自然规则出现；这一事实不因购买展示而变化。

因此允许“同一站点在赞助位与自然榜都出现”，但不允许把赞助位伪装成自然排名结果，或用 sticky/默认排序偷偷改变自然表。

### 3.2 覆盖的用户入口

- 中转站主列表及其 SSR 首屏；
- 筛选、排序或分页后由浏览器脚本载入/重排的列表；
- 模型详情中引用的中转站结果；
- 与上述入口直接共用的行组件、数据组装与多语言文案。

实现前 p001 必须将真实文件、函数、数据字段和当前不同入口的差异写入任务证据；不得只凭本文件猜测改动位置。

## 4. 明确排除项

- 不接入新公开榜单，不发起真实网络采集，不改变 raw -> merge/import 生命周期；每日运行仍由本机 GUI 的人工按钮或同一 CLI 触发。
- 不增加 `--loop`、定时器、并发 worker、生产采集器或生产统计任务。
- 不实施开源基准自测；待用户提供明确仓库、revision、运行成本与复现实例后另行建单。
- 不建立 AIGATE 新综合评分、权重公式、阈值、数据库 schema 或平行数据管道。
- 不做部署、SEO 内容扩张、付费套餐/价格、商家合同生命周期、支付结算或 CRM。
- 不改商店/商品 sponsored pinning 等非中转站页面；若 p001 发现共享逻辑会影响该页面，先以独立后续任务报告，不扩大本 M1。

## 5. 实施与测试要求

1. 在 p001 的审计结论基础上，先写会失败的针对性测试：改变赞助状态不得改变同一自然输入的顺序或分数；没有赞助输入时输出保持不变。
2. p002 在服务端/视图组装层完成数据隔离，不能仅用 CSS 隐藏或前端排序补救。
3. p003 必须同时处理服务器渲染与客户端动态加载，不能只修初始 HTML。自然结果表保留完整、正常可筛选/排序并对键盘与读屏可理解。
4. p004 文案至少覆盖中文、英文、俄文现有 locale。若不存在可靠的“纠错”后端，复用已有联系/反馈路径或可配置联系文本；不要虚构“已受理”的自动承诺。
5. p005 至少运行适用的 `pnpm test`、`pnpm run typecheck`、`pnpm run build`。使用 `pnpm exec astro dev status` 确定实际本地入口后，在浏览器从真实路由验证主列表、筛选/动态内容和模型详情。只报告真实命令与截图/浏览器事实；不将本机验证表述成生产结果。

## 6. 完成定义

只有以下全部成立才可将 p005 标为 `done`：

1. 自然榜不含赞助驱动的 sticky/置顶，且赞助状态前后自然顺序与自然分数不变；
2. 赞助内容在每个覆盖入口均具有不依赖颜色的明确文案标识；
3. 用户仍可获得完整自然结果并理解评分/来源的真实语义；
4. 付费链接属性、locale、SSR、动态加载和关键浏览器路径均有测试证据；
5. 没有引入采集、调度、统计、数据库 schema、生产部署或新评分系统；
6. 每项任务按仓库 taskexec 规则留存 claim、tasklog、QA、Git 和 review 字段，且提交只包含本清单范围内的文件。
